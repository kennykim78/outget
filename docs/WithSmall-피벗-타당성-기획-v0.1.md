## 0. 결론 (Bottom line)

**사업으로는 약하고, 무료 유틸리티+커뮤니티로는 성립한다. 단, 기획서의 핵심 정책 2개(3단계 분양·"95% 승계")는 사실과 어긋나므로 고쳐야 진행 가능하다.**

| 판정 축 | 결론 | 근거 요약 |
|---|---|---|
| 시장 규모 | **작다** — 니치 중의 니치 | 정부·KB 조사 모두 조류·설치류를 별도 집계조차 안 함. 반려 591만 가구 중 조류+설치류는 한 자릿수 % 추정 → 10~20만 가구 규모, 그중 연간 분양 이벤트는 일부 |
| 지불의사 | **분양 측 0, 용품 저단가** | 분양은 무료가 원칙(법적으로도). 수익은 어필리에이트·병원 스폰서십뿐 → 1인 운영비 회수 수준이 상한 |
| 법적 제약 | **기획서보다 무겁다** | 반려동물 6종(햄스터·기니피그·토끼·페럿) 유료분양 = 무허가 판매업 리스크, 플랫폼 "알선·중개" 정의 리스크. 앵무·기타 설치류는 CITES + 2025.12 백색목록·양도양수 신고제 |
| 경쟁 | **직접 경쟁 1(동물다락), 대체재는 네이버 카페** | 동물다락: 인증 업체 B2C·경매·라이브, 1만+ 다운로드. C2C 무료 분양+안전게이트는 비어 있음 |
| 콜드스타트 | **양면 + 반경 5km → 밀도 문제가 치명적** | 전국 월 수천 건을 서울 동 단위로 쪼개면 하루 0~2건. 지도 우선 UX는 초기에 빈 화면을 만든다 |
| 기존 자산 | **서버 ~60% · 클라 ~40% 재활용**, 현재 빌드 깨짐 | 스키마만 교체되고 Outget 모듈 고아화(`tsc` 실패). WithSmall 화면 0개, 업로드 인프라 0 |

**진행 조건 (Go if all):**
1. 목표를 "수익 사업"이 아니라 **"운영비 ≤ 월 수만 원의 무료 공공재 + 포트폴리오"**로 재정의한다. 수익화는 Phase 3 이후 옵션.
2. 분양 정책을 **종별 법체계에 맞춰 분기**한다(§2). 6종은 무료만, 앵무새는 신고 체크 하에 유료 허용.
3. 지도-우선이 아니라 **리스트-우선 + 지도 보조**로 UX를 뒤집는다(§5). 밀도가 생기기 전까지 지도는 병원 맵에서만 주역.
4. 순서를 **병원 맵(단면) → 용품 나눔(저위험 양면) → 분양(고위험 양면)**으로 놓고, 각 단계에 중단 기준을 둔다(§4).

## 1. 시장성 — 냉정한 수치

### 1.1 수요 규모 (추정, 가정 명시)
- 반려가구 591만(전체 26.7%), 반려인 29.9%. 수도권 51.7%(경기 26.6%). — KB 2025 보고서
- 개 455만 가구 / 고양이 137만 가구. **조류·설치류·토끼는 미집계.** 정부 조사(2024 동물복지 국민의식조사)도 개·고양이 두수만 발표.
- 가정: 조류+설치류+토끼 양육 비중 2~4% → **약 12~24만 가구**. 햄스터 수명 2~3년·다산, 앵무새 수명 10~50년 → 분양 이벤트는 햄스터 쪽이 압도적으로 빈번하지만 개체 가치는 0.
- 입양 경로(전체 반려동물): 지인 31.5% · 구조/보호소 27.7% · 펫숍 25.2%. 소동물은 펫숍(다이소·대형마트 포함)과 커뮤니티 카페 비중이 더 높을 것으로 추정.

**함의:** 전국 월간 활성 분양글이 수천 건 수준이라 해도, 반경 5km 필터를 걸면 서울 외곽·지방은 **빈 화면**. 지도 UX는 "동네"가 아니라 "시·도" 단위로 시작해야 한다.

### 1.2 경쟁·대체재
| 플레이어 | 성격 | 우리와의 관계 |
|---|---|---|
| **동물다락**(펫팸브랜딩, 2024~) | 열대어·파충류·이색동물, **인증 업체 중심 B2C**, 경매/역경매, 라이브, 커뮤니티. 1만+ DL, 4.7★(99) | 가장 가까운 직접 경쟁. 업체 중심이라 **C2C 무료 분양·안전게이트는 비어 있음**. 파충류 커뮤니티 인플루언서(정브르) 기반 |
| 네이버·다음 카페(햄스터/앵무새/기니피그 카페 다수) | 텍스트 게시판, 회원 수십만 규모 추정, 분양·나눔 게시판 운영 | **실질 대체재이자 최대 유입원.** 위치 탐색·신청서·신고 체계 없음 → 우리의 차별점. 동시에 여기서 사용자를 빼오지 못하면 끝 |
| 당근 | 중고거래 게시판에서 동물 관련 게시글(맡기기 포함) 제한, 반복 시 제재 | 공백을 만든 장본인. 단 **용품**은 당근에서 자유롭게 거래됨 → 용품 장터는 당근과 정면 경쟁 |
| 포인핸드 | 유기동물 입양·실종. 개·고양이 중심 | 간접. 협업 여지(소동물 유기 케이스) |
| 주세요닷컴, 한동연 등 | 웹 무료분양 게시판, 설치류 카테고리 존재 | 낡은 UX. 존재 자체가 "수요는 있으나 작다"는 증거 |

### 1.3 수익 상한
- 분양: 0원(법·윤리·커뮤니티 정서 모두).
- 용품 어필리에이트: 케이지·쳇바퀴·펠렛 객단가 2~15만 원, 커미션 1~3% → 월 1만 클릭·전환 2%면 **월 수십만 원**.
- 특수동물 병원 스폰서십: 전국 특수동물 진료 가능 병원 자체가 수십 곳 수준(기사 기준 10~15곳 "전문", 진료 가능 병원은 더 많음) → 광고주 풀이 극소.
- **결론: 1인 운영 서버비 회수는 가능, 인건비 회수는 불가.** 이 프로젝트의 가치는 매출이 아니라 (a) 커뮤니티 자산, (b) 지도·양면·컴플라이언스 아키텍처를 실제 트래픽에서 검증한 포트폴리오다.

## 2. 법적 제약 맵 — 기획서를 바꾸는 부분

기획서는 "동물보호법 + CITES"만 봤다. 실제로는 **3개 체계가 종별로 다르게** 걸린다.

| 종 그룹 | 적용 법체계 | 개인 유료 분양 | 무료 나눔 | 플랫폼이 해야 할 것 |
|---|---|---|---|---|
| **A. 반려동물 6종** — 개·고양이·**토끼·페럿·기니피그·햄스터** | 동물보호법(2023.4.27 허가제). 동물판매업 = "반려동물을 구입하여 판매·**알선·중개**하는 영업". 무허가 영업 2년 이하 징역/2천만 원 이하 벌금 | **금지 수준의 리스크.** 1회성 유료도 문제될 수 있다는 자문 사례 존재. 책임비도 회색(소액 허용 개정안은 미통과) | 적법 | **가격 필드 자체를 없앤다**(0원 고정). 유료 매칭을 붙이면 플랫폼이 "알선·중개" 영업 해당 리스크 → 무료·무수수료 구조가 법적 방어선 |
| **B. CITES 앵무새** — 코뉴어·퀘이커·카이큐·모란(복면모란 제외)·코카투·회색앵무 등 | 야생생물법 국제적 멸종위기종. 양도·양수 신고(환경청). 회색앵무 등 부속서 I은 허가+사육시설 등록 | 허용(신고 조건부). 동물보호법 "반려동물"이 아니므로 판매업 허가 불요 | 신고 필요 | 종 선택 시 **CITES 등급 자동 표시**, 신고 안내·체크 강제, 부속서 I 종은 등록 차단(허가증 확인 불가) |
| **C. 비CITES 조류·기타 설치류** — 사랑앵무·왕관앵무·복면모란·십자매·문조 / 친칠라·데구·저빌·슈가글라이더·고슴도치·래트 | 야생생물법 **지정관리 야생동물(백색목록)** 제도, 2025.12.14 시행. 백색목록(포유류 9·조류 17·파충류 655·양서류 207종) 외 종은 양도·양수·보관 원칙 금지. **무료 나눔도 양도·양수 신고 대상**(월별, 익월 10일까지), 미신고 과태료 최대 100만 원 | 백색목록 종에 한해 허용 | 신고 필요 | **종 마스터 테이블에 백색목록 여부를 박아** 미등재 종은 등록 차단. 사랑앵무·왕관앵무의 백색목록 등재 여부는 고시 원문으로 확인 필요(미확인 시 런칭 범위에서 제외) |

추가 공통 제약:
- **동물 택배 금지**: 기획서의 "동물보호법 제9조 제3항"은 구법 조문 번호. 현행은 제11조(동물의 운송) + 우편법상 생물 우편 금지 + 택배 약관. 조문 인용은 갱신 필요, 정책 자체는 유지.
- **온라인 판매 광고 규제 강화 움직임**: 동물단체가 온라인 판매 과태료 상향(100→500만 원)과 인터넷 광고 금지, 정보통신망법상 게시판 관리자 조치 의무 입법을 요구 중(2026.1). 통과 시 **플랫폼의 유료 분양글 관리 의무가 법정화**될 수 있음 → 6종 무료 전용 정책은 여기서도 방어가 된다.
- **통신판매중개 최소 의무**(Outget 불변식 ③)는 그대로 유효. 단 6종 무료·앵무 유료로 갈리면 "중개" 표현을 앵무 유료 건에만 붙이는 것이 안전.

**기획서 수정 결정:**
1. "3단계(무료/책임비/개인유료)"를 **종 그룹별 허용 매트릭스**로 교체. A그룹은 무료만. 책임비는 런칭 범위에서 제외(법률 자문 후 재검토 항목으로 이관).
2. `AdoptionPost.category` 5개(HAMSTER/PARROT/GUINEA_PIG/RABBIT/OTHER)를 **종 마스터(Species) 참조**로 바꾸고, 법체계·CITES 등급·백색목록 여부를 종 단위로 보유. "OTHER" 자유입력은 차단.
3. 분양 완료 시 **양도·양수 신고 리마인더**(B·C그룹)를 플랫폼 기능으로 제공 — 이것이 카페 대비 실질 차별점이자 "합법 분양 플랫폼" 포지셔닝의 근거.

## 3. 현 작업물 재활용 진단 (실측)

### 3.1 코드 상태
- 마지막 커밋 `2e00199`(Outget 완성형). 이후 **미커밋** 변경: `schema.prisma` WithSmall로 전면 교체, `app.ts`·`repos.ts` 수정, `adoption/ application/ supply/ vet/` 4모듈 신규.
- `tsc --noEmit` **실패**: Outget Prisma 리포(agent·match·discount·bounty·groupslot·request)가 삭제된 모델을 참조. `supply.routes.ts`는 존재하지 않는 `AuthContext` import. → **현재 서버는 빌드 불가.**
- 클라이언트: WithSmall 화면 0개. `AdoptRequestButton.tsx` 1개만 존재(agent 폴더 내, 맥락 불명).
- 채팅: `chat.routes.ts`가 `Match`(Outget 매칭)에 당사자 인가를 묶어둠. `application.routes.ts`가 만드는 `chatThreadId = chat_{post}_{applicant}`는 **아무 라우트에도 연결되지 않음** → 신청 수락 후 대화 불가.
- 사진: `photos`/`cagePhotoUrl` 모두 문자열 URL. **업로드·저장·리사이즈 인프라 없음.** 사육환경 사진 게이트가 핵심인데 구현 기반이 0.
- 테스트: 서버 21파일(Outget 도메인 위주, 스키마 교체로 Prisma 경로 테스트는 깨질 것), 클라 1파일.

## 5. UI/UX 기획

### 5.1 IA — 기획서 대비 변경
기획서: 홈=지도 & 바텀시트. **변경: 홈=리스트(피드) + 지도 토글.** 이유는 §1.1 밀도.

```
[탭] 홈(피드)   병원맵   글쓰기   채팅   마이
 홈 ── 카테고리 알약: 전체 · 햄스터 · 기니피그·토끼 · 앵무새 · 기타소동물 · 용품
    ── 지역 선택: 시/도 → 시/군/구 (동 단위 아님, 반경 아님)
    ── 정렬: 최신 · 거리(위치 허용 시)
    ── 카드 리스트 ⇄ 지도 보기 토글 (지도는 분양+용품 핀, 게시 5건 미만이면 지도 토글 숨김)
 병원맵 ── 지도 주역. 진료 가능 동물 필터(햄스터/기니피그/토끼/앵무/파충류/야간)
 글쓰기 ── 분양글 / 용품글 (종 선택이 첫 단계 → 법적 상태 즉시 표시)
 채팅 ── 상담방 목록 · 받은/보낸 신청서
 마이 ── 프로필 · 뱃지 · 내 신고 · 신고 리마인더(양도·양수)
```

### 5.2 화면별 기획

**S1 홈 피드** (BoardView 셸 재사용)
- 카드: 대표 사진 · 종/품종 · `무료분양` 또는 `개인양도 ₩` 태그 · 나이/성별 · 시군구 · 법적 배지(`CITES 신고 대상` / `백색목록` / 해당 없음) · `사육환경 인증 필수`.
- 빈 상태: "아직 우리 지역엔 글이 없어요 — 병원 맵 보기 / 첫 글 쓰기" (EmptyState 재사용).
- 지도 토글은 게시 밀도 조건부 노출.

**S2 글쓰기 — 종 선택 우선 (신규, 핵심)**
1. 카테고리 → **종 검색/선택**(마스터 테이블). 선택 즉시 법적 상태 카드 표시:
   - A그룹: "이 친구는 무료 분양만 가능해요. 금액 입력은 없어요." (가격 필드 렌더 안 함)
   - B그룹: "CITES 부속서 II — 분양 완료 후 환경청 양도·양수 신고가 필요해요." + 서류 준비 체크 필수. 부속서 I은 등록 차단 안내.
   - C그룹: 백색목록 등재 → "양도·양수 신고 대상(익월 10일까지)" 안내. 미등재 → 등록 차단.
2. 개체 정보(사진 최대 5장 업로드·성별·나이·건강) → 3. **입양 조건 체크리스트**(케이지 규격, 단독 사육 등 프리셋 + 자유입력) → 4. 사연 → 5. 지역(시군구) + 대면 인도 서약 체크(택배 불가 고지).

**S3 분양 상세** (기획서 5.2 유지, 추가: 법적 상태 카드 상단 고정, 통신판매중개 고지는 유료 앵무 건에만, 무료 건은 "플랫폼은 분양 당사자가 아닙니다"로 간소화)

**S4 입양 신청서 모달** (기획서 5.3 유지, 변경 2건)
- Step 1 사육환경 사진: **업로드 필수 + 촬영 시각 안내**("최근 촬영본"). EXIF 검증은 하지 않되(오탐·개인정보), 신청자당 동일 이미지 재사용은 해시로 감지해 분양자에게 표시("이 사진은 다른 신청에도 사용됨").
- Step 2 서약에 종별 항목 추가: 햄스터 "단독 사육", 앵무 "신고 협조", 기니피그 "2마리 이상 권장" 등 종 마스터에서 로드.

**S5 채팅** (ChatView 재사용)
- 상단 고정 배너: 선입금 금지·대면 인도·이동장.
- 액션: `대면 약속 잡기`(장소 텍스트 + 시간, 지도 핀 옵션) · `신고 서류 안내`(B·C그룹만 노출) · `신고`.
- 분양자 `입양 완료` → 양측 뱃지 + B·C그룹은 **신고 리마인더 생성**(마이 탭에 D+10 알림).

**S6 용품 장터** (기획서 5.5 유지) — 카드 첫 자리에 `무료나눔` 강조, 당근과 동일 관행. 신청서 없이 바로 채팅.

**S7 병원 맵** (기획서 5.6 유지) — Phase 0 주역. 병원 카드에 "진료 가능 동물"·"야간"·"제보하기"(UGC 보정, notice-and-takedown 적용).

### 5.3 카피·시각 원칙
- 법적 상태는 **색+아이콘+문구** 3중(기존 의미색 규칙 계승): 해당없음(회색) / 신고 대상(앰버) / 등록 불가(적).
- "판매"·"거래" 단어를 A그룹 화면에서 제거. "분양·나눔·입양"만.
- 통신판매중개 고지는 **금액이 표시되는 화면에만**.

## 6. 아키텍처

### 6.1 시스템 구성 (변경분 중심)
```
client (Vite+React PWA)                 server (Express ESM)                 DB (SQLite→Postgres M2)
 ├ board/  셸 재사용, 카드 교체            ├ auth/ governance/ notification/     User, RefreshToken
 ├ map/    그대로                          │   chat(message)/ badge/  ← 유지     Species(신규 마스터)
 ├ adoption/ 글쓰기·상세·신청서 (신규)     ├ species/   마스터+법적 판정 (신규)   AdoptionPost(+speciesId)
 ├ supply/  피드·글쓰기 (신규)             ├ adoption/ application/ supply/ vet/ AdoptionApplication
 ├ vet/     병원맵 (신규)                  │   ← 유지·보강                        SupplyPost, VetClinic
 ├ chat/    재사용, 컨텍스트 키 교체        ├ upload/   이미지 업로드 (신규)        Report, Dispute, Badge
 └ upload/  이미지 선택·압축 (신규)        ├ reminder/ 양도양수 신고 리마인더(신규) Message, Notification
                                           └ [삭제] agent request board/discount  ComplianceReminder(신규)
                                                    bounty groupslot shopping payment
```

### 6.2 데이터 모델 변경
- **`Species`(신규 마스터, 시드)**: `id, category, nameKo, nameSci, legalGroup(A|B|C), citesAppendix(null|I|II|III), whitelistListed(bool|null=미확인), allowPaid(bool), pledgePreset(JSON), careMinSpec(JSON)`. 종 추가는 운영자만.
- **`AdoptionPost`**: `category`+`speciesDetail` → `speciesId` FK + `speciesDetail`(품종 자유입력). `dealType` enum을 `FREE|PAID_TRANSFER`로 축소(DEPOSIT 제거). `price`는 `allowPaid=false`면 서버가 0 강제(400). `citesSpecies/citesDocReady` → 종 마스터에서 파생, 입력은 `docReady`만.
- **`AdoptionApplication`**: `cagePhotoUrl` → `cagePhotoIds(JSON)` + `photoHash`. `familyAgreed`+`commitment` → `pledges(JSON)`(종별 프리셋 응답).
- **`Photo`(신규)**: `id, ownerId, kind(POST|CAGE|SUPPLY), path, sha256, createdAt`.
- **`ComplianceReminder`(신규)**: `id, userId, postId, kind(CITES|WHITELIST), dueAt, done`.
- **`Message`**: `threadId`를 `AdoptionApplication.chatThreadId` 또는 `SupplyThread.id`로 통일. 당사자 인가는 `thread → (post.authorId, applicantId)` 조회로.

### 6.3 핵심 서버 규칙 (불변식 갱신 — CLAUDE.md 교체 대상)
1. **자금 미보유·무수수료** (유지). 앵무 유료 건도 금액은 표시값, 결제 코드 0.
2. **종별 허용 매트릭스는 서버가 강제** — 클라 UI는 표시일 뿐. `allowPaid=false` 종의 `price>0`은 400, `whitelistListed=false`·`citesAppendix=I` 종은 등록 400.
3. **사육환경 사진 없으면 신청 불가** (유지, 업로드 실체화).
4. **동물 택배 금지 고지** + 채팅 본문에 택배·퀵·고속버스 키워드 시 경고 배너(차단 아님).
5. **notice-and-takedown** (유지). 신고 사유 enum: `PAID_SALE_OF_FREE_ONLY_SPECIES, FEEDER_SUSPECTED, HOARDER_SUSPECTED, CITES_VIOLATION, SHIPPING_SOLICITED, FRAUD`.
6. **위치 비실시간** (유지): 시군구 텍스트 + 게시글 옵션 핀. 사용자 좌표 저장 안 함.
7. **무크롤링** (유지): 병원 DB는 운영자 시드 + UGC 제보만.

### 6.4 업로드 설계 (단일 컨테이너 전제)
- `multer` → 로컬 `/data/uploads/{yyyy}/{mm}/` 저장, `sharp`로 1600px 리사이즈·EXIF 제거·WebP. 정적 서빙은 `/uploads` 라우트(인증 불요, 경로 추측 불가한 UUID 파일명).
- 용량 제한 5MB/장, 게시글 5장·신청서 3장. sha256로 신청서 사진 재사용 감지.
- M2(Postgres 전환)와 함께 객체 스토리지(NCP Object Storage/S3)로 이전 — 포트 인터페이스(`PhotoStore`)로 격리.

### 6.5 복구·마이그레이션 순서 (Phase 0 첫 주)
1. 현재 미커밋 상태를 `wip/withsmall-pivot` 브랜치로 커밋(증거 보존).
2. Outget 전용 모듈 삭제: `agent/ request/ board/discount* board/listings* bounty/ groupslot/ shopping/ payment/` + 해당 테스트 + `client/src/{agent,request,discount,bounty,groupslot}`.
3. `repos.ts`·`app.ts`에서 위 참조 제거 → `tsc` 통과 확인.
4. `Species` 모델·시드 추가, `AdoptionPost` 스키마 수정, Prisma 마이그레이션 초기화(기존 Outget 마이그레이션 히스토리는 폐기 — 프로덕션 데이터 없음).
5. `chat.routes.ts` 당사자 인가를 `Application/SupplyThread` 기준으로 재작성 + 테스트.
6. `upload/` 모듈 + `PhotoStore` 포트.
7. `compliance-scan.mjs` 규칙 교체(결제 코드 0, 6종 price 강제, 실시간 좌표 금지).
8. CLAUDE.md 불변식·하네스 설명을 §6.3으로 교체, 제품명·역할 enum 정리.
9. 클라이언트: App.tsx 라우팅을 5탭으로 교체, `vet/` 화면부터.

## 7. 미결 — 자문·확인 항목 (진행 전 닫아야 함)
1. **백색목록 조류 17종·포유류 9종 원문**(환경부 고시): 사랑앵무·왕관앵무·복면모란·십자매·문조·친칠라·데구·저빌·고슴도치 등재 여부 → `Species.whitelistListed` 값 확정. 미확인 종은 런칭 제외.
2. **"알선·중개" 해당성**: 무료·무수수료 플랫폼이 6종 무료분양을 게시·매칭하는 것이 동물판매업 "알선"에 해당하지 않는지 변호사 확인. 앵무 유료 건의 통신판매중개 고지 문안 포함.
3. **책임비**: 소액 허용 개정 동향 추적. 통과 전까지 A그룹은 0원 고정.
4. **온라인 판매 광고 규제 입법**(과태료 상향·게시판 관리자 의무): 통과 시 유료 게시글 사전 검수 의무 발생 가능 → 앵무 유료 건 운영 정책 준비.
5. **동물 운송 조문 번호 갱신**(구 §9 → 현 §11) 및 우편법 근거 문구.
6. 병원 데이터 시드 출처: 지자체 동물병원 인허가 공공데이터(진료 동물 필드 없음) + 커뮤니티 제보 → UGC 보정 정책.
