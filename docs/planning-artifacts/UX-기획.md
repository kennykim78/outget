## 0. 왜 다시 설계했나

v1.x는 기능적으로 맞았지만 **"준비해야 할 일의 목록"이 첫 화면**이라 관리자·CRM 도구처럼 보였다. 소비자 서비스의 리듬은 **발견 → 선택 → 도구**다(미리캔버스: 결과물이 가득한 첫 화면, 고르면 편집기가 열린다). v2.0의 원칙: **겉은 서비스, 속은 도구.** 홈은 카드와 레일로 발견하게 하고, 체크리스트·규격 확인·2질문은 레이어 안에서만 도구로 존재한다.

## 1. 디자인 원칙 (v2.0)

1. **한 화면 = 한 결정, 한 홈 = 하나의 다음 발견.** 홈은 "무엇을 해야 하지"만이 아니라 "다음에 무엇을 볼까"를 유도한다.
2. **동물을 고르는 순간 홈 전체가 개인화된다.** 동물 미선택 시 레일은 일반형("요즘 많이 찾는 준비"), 선택 시 "골든햄스터를 위한 준비"로 바뀐다. 이 전환이 "정적 정보 DB"와 "살아 있는 서비스"를 가른다.
3. **행동이 숫자보다 먼저.** "필수 2개 남았어요"가 진행률보다 먼저. 유지.
4. **근거는 항상 옆에.** 상품 카드에는 언제나 `✓ 기준 충족`이 붙고, 판정에는 이유와 검수일이 붙는다. 신뢰 수치화 금지. 유지.
5. **안 사도 되는 것을 숨기지 않는다.** NOT_NOW는 체크리스트 레이어에서 접혀 있되 보인다. 유지.
6. **시각 비중 고정: 캐릭터 > 구성안 > 용품 > 상품.** 상품 카드가 화면의 절반을 넘으면 쇼핑몰이 된다. 상품은 네 번째 레일이고 크기는 가장 작다.
7. **PC는 모바일의 확장이지 다른 제품이 아니다.** 상하 흐름 동일, 넓어지면 레일의 카드 수만 는다. 좌측 내비·고정 패널·2열 CRM 구조 없음.
8. **마스코트는 진입·개인화·빈 상태·완료에만.** 판정·규격·병원 상세·법적 안내에는 없음. 유지.
9. **의료 단정 금지, 흰 바탕 단일 테마.** 유지.
10. **콜드스타트는 '왜 WithSmall인가', 선택 홈은 '그래서 무엇을 준비할까'.** 미선택 홈은 4섹션(친구 선택 · 실제 이용 후기 · WithSmall 소개 · 시작 배너), 선택 홈은 5섹션(지금 필요한 것 · 처음 준비한다면 · 기준에 맞는 준비물 · 동네 병원 · 가입 배너). 소개는 스크롤할 때마다 한 내용만 보이는 전환형, 주요 기능은 큰 이미지 좌 · 짧은 글 우 카드. 그룹 카드·카테고리 카드·스텝/특징 격자는 홈에 두지 않는다.
11. **캐릭터는 대표 마스코트 하나, 나머지는 실사.** 마스코트는 히어로·동물 칩·L1·빈 상태·완료에만. 설명 블록·그룹 카드·용품 카테고리·쇼케이스의 사진 자리는 실사(운영자 촬영·사용권 확보 스톡)로 채운다. 아이콘·이모지로 대신하지 않는다(구성안 글리프 🌿☁♻·상태 글리프 제외).
12. **가입은 작고 자연스럽게 — '하다 보니 저장하고 싶어지는' 순서.** 이메일 링크 인증만, 저장 대상은 선택 동물·체크 상태·내 케이지뿐. 유도는 **2곳**: 선택 홈 밴드("다른 기기에서도 이어서 — 이메일로 저장")와 L2 푸터("지금 준비 상태를 저장해 둘까요?"). 콜드스타트 홈·히어로·PC 헤더에는 없음. 모달 강제·가입 게이트·기능 잠금 없음.

## 2. 정보구조

### 2.1 내비게이션 (모든 폭 공통: 상단 글로벌 헤더)
```
[WithSmall 로고]   [🐹 골든햄스터 ▾ | 친구 선택]   용품 찾기   병원          (PC: 우측 정렬 텍스트 메뉴)
모바일: 로고 · 동물 칩(탭하면 선택 레이어) · 하단 탭 3개(홈 · 용품 · 병원)
```
좌측 레일 없음. 동물 칩이 "현재 컨텍스트"이며 어디서든 바꿀 수 있다.

### 2.2 페이지와 레이어
```
페이지 (URL, 프리렌더, 상하 흐름)
 /                         홈 — 히어로 · 지금 필요한 것 · 처음 준비한다면 · 기준에 맞는 준비물 · 우리 동네 병원
 /{group}/{type}           동물 홈 — 홈과 같은 골격, 동물 컨텍스트 고정 (SEO 랜딩)
 /{group}/{type}/setup     구성안 페이지 — 3안 상세, 항목 → 레이어
 /supplies, /supplies/{item}   용품으로 찾기 — 카테고리 그리드 → 동물 선택 → 용품 레이어
 /vet, /vet/{region}       병원 — 리스트|지도, 전문 도구 톤
 404 · PLANNED · 오프라인

레이어 (부모 페이지는 유지되고 URL만 history state로 확장: `/hamster/golden` → `/hamster/golden/supplies/wheel`, 뒤로가기 = `/hamster/golden`. 딥링크 시 "부모 페이지 + 레이어 열림"으로 렌더. 모바일 바텀시트 / PC 센터 모달·와이드 드로어)
 L1 동물 선택      소동물|앵무새 → 세부 타입 → "잘 모르겠어요"(별칭)
 L2 체크리스트     필수/권장/선택/NOT_NOW, 상태 엔진, [내 상황 다시 설정]
 L3 2질문          처음/이미 · 가진 것 (L2 첫 진입 시 L2 안에서 스텝으로)
 L4 용품 상세      왜/조건/주의/피할 것/대안 · 내 케이지 호환 · 하단 [규격 확인][이 조건으로 찾기]   URL /{group}/{type}/supplies/{item}
 L5 규격 확인      specSchema 폼 · 내 케이지 · 2단 판정                                        URL /{group}/{type}/check/{item}
 L6 내 케이지      타입·치수 (L5·L2에서 스텝으로)
 L7 상품 상세      이미지·규격 한 줄·WithSmall 추천 이유(자동 조립)·♥ · [이 조건으로 찾기]      URL /{group}/{type}/products/{id}
 L8 이메일 저장    이메일 입력 → 인증 메일(매직 링크) · 저장 대상 요약 · [나중에 할게요]                     URL /save
```
레이어 규칙: 한 번에 하나만 열림(스텝 전환은 같은 레이어 안). 닫으면 부모 페이지의 스크롤·상태 그대로. 뒤로가기는 레이어를 닫는다. 프리렌더는 부모 페이지 + 레이어 본문을 정적 HTML에 포함(SEO).

## 3. 홈 (`/`, `/{group}/{type}`)

### 3.1 두 개의 홈 (고정)
**A. 동물 미선택(콜드스타트) — 4섹션**
```
① 친구 선택      마스코트(112/120) + "작은 친구를 처음부터 제대로 준비해요" + [어떤 친구인가요?] 하나 + 그 아래 기능 칩 4개 한 줄(지금 필요한 것 · 규격 판정 · 구성안 · 동네 병원, 탭하면 ③의 해당 슬라이드로 앵커 스크롤) — 주요 기능의 '가로 간결 요약'은 이 칩 줄이 담당
② 실제 이용 후기  **흐르는 레일(마퀴) 2줄 역방향**(호버·터치 시 정지, `prefers-reduced-motion`이면 정지+수동 스크롤). ReviewCard = 문장("어떤 문제가 해결됐나") + **리뷰어 사진 40px 원형**(동의분만, 없으면 동물 마스코트 칩 아님 — 회색 이니셜 원) + 동물·상황("골든햄스터 · 처음 준비") + "이용 확인" 칩 + 다음 행동 링크. 별점 없음
                 노출 사다리: 0개 → 섹션 숨김 / 1~2개 → 큰 카드 1장(정지) / 3~5개 → 정지 레일 / **6개↑ → 마퀴 2줄** / 충분히 쌓이면 동물별
                 `verifiedUsage=true`(실제 체크 상태·판정 이력이 있는 사용자)이고 운영자 승인된 것만. 시안 문구는 예시이며 실서비스에서 임의 작성 금지
③ WithSmall 소개  한 화면 한 내용 × 4 = 주요 기능을 흡수(지금 필요한 것 / 규격 판정(+찾기) / 구성안 / 동네 병원). 모바일 세로 슬라이드 / PC 좌 sticky 사진 + 우 항목(활성 1개만 펼침). 별도 '주요 기능' 섹션 없음
④ 시작 배너      brand-soft: "어떤 친구와 함께하시나요?" + CTA + "가입 없이 바로 시작해요" · 푸터 한 줄 (저장 유도 없음)
```
**B. 동물 선택 — 컨텍스트 헤더 + 5섹션** ("골든햄스터를 위한 …")
```
컨텍스트 헤더     마스코트 96 + 동물명 + 상태 한 줄 + [친구 바꾸기]. 섹션으로 세지 않는다
① 지금 필요한 것   L3(2질문) 완료 전: "필수 준비를 먼저 확인해요" + 기본 REQUIRED 칩만(숫자 없음). 완료 후: "필수 2개 남았어요" + 상태 반영 칩   비중 ██████
② 처음 준비한다면   BundleCard 레일 3 — 시각 순서 구성 철학 → 포함 항목 → 참고 범위(가격이 가장 큰 숫자가 되지 않게)              비중 ██████
③ 기준에 맞는 준비물 ProductCard 레일 → L7                                                                                    비중 ████
④ 우리 동네 병원    VetCard 레일 + 전체 → /vet                                                                                비중 ████
⑤ 저장 배너        "골든햄스터 준비, 이어서 할까요?" + [지금 필요한 것 보기] + "다른 기기에서도 이어서 — 이메일로 저장"
```

## 4. 레이어 명세

**L1 동물 선택** — 그룹 2 → 타입 카드(ACTIVE/PLANNED) → "잘 모르겠어요" 텍스트 입력·별칭 후보(종 확정 안 함). 선택 즉시 닫히고 홈이 개인화됨(`species_selected`).
**L2 체크리스트** — 상단 "오늘 바로 데려와도 되는 준비 · 필수 2개 미완료" + 진행바, 4그룹 행(상태 엔진 ✓ ! △ ○, 보유 라벨, NOT_NOW 이유·접힘), [내 상황 다시 설정](L3 스텝). 행 탭 = L4로 교체(뒤로가기 시 L2 복귀). 첫 진입엔 L3가 먼저 스텝으로 뜬다(건너뛰기 가능).
**L4 용품 상세** — 섹션 순서 고정(왜 → 조건 → 주의 → 피할 것 → 대안 → 내 케이지 호환 서브카드) + 푸터 [규격 확인][이 조건으로 찾기] + 👍 ⚠ + 검수일. 하단에 "이 항목에 맞는 준비물" 상품 카드 2~3(있을 때).
**L5 규격 확인** — specSchema 폼, 내 케이지(L6 스텝), **2단 판정**(제품 규격 / 내 환경 호환), 대안, [이 조건으로 찾기].
**L8 이메일 저장** — 제목 "이메일로 저장해 둘까요?", 설명 "선택한 동물과 준비 상태만 저장해요. 비밀번호 없이 메일의 링크로 확인해요.", 이메일 입력 1개, 저장 대상 요약 한 줄(동물 칩 · 필수 N개 남음 · 내 케이지), [인증 메일 보내기] 하나, [나중에 할게요] 아웃라인, "광고 메일은 보내지 않아요". 링크 클릭 시 로컬 상태를 서버로 병합(로컬 우선). 로그인 상태 표시는 헤더 칩 옆 작은 점 하나.
**L7 상품 상세** — 이미지(운영자 확보분) · 상품명 · 용품 종류 · 규격 한 줄 · **WithSmall 추천 이유(자동 조립: 규격 충족 · 프로필 일치 · 호환)** · 검수일 · ♥ · [이 조건으로 찾기](검색 딥링크). 가격·판매처·제휴 없음(Phase 1). "구매" 단어 없음.

## 5. 상품 표면 규칙 (Phase 0 = 발견, 판매 아님)
- 카드: 이미지(1:1, 상품이 화면의 주인공이 되지 않도록 카드 폭 ≤ 200), 상품명 1줄, 규격 한 줄(`30cm · 무소음`), `✓ 기준 충족` 배지(항상), ♥(반응 수는 임계치 이상일 때만 숫자 표시, 미만은 아이콘만).
- 레일 제목은 "기준에 맞는 준비물"(검수 기준) — "많이 선택한 준비물"(♥ 기준)은 데이터가 쌓인 뒤 별도 레일로, 절대 같은 레일에 섞지 않음. 노출 순서 규격→검수→선호 고정.
- 이미지 출처: 운영자가 사용권을 확인한 이미지(직접 촬영·판매자 허가·제휴 API 제공분)만. 외부 페이지 자동 수집 금지. 이미지 없는 상품은 카드에 용품 아이콘 타일로 대체.
- 상품 카드에 캐릭터·가격·"최저가"·"베스트" 없음.

## 7. 카피 (변경분)
- 섹션 제목 고정: "지금 필요한 것" / "처음 준비한다면" / "기준에 맞는 준비물" / "우리 동네 병원". 미선택 시 "요즘 많이 찾는 준비".
- 상품 카드: "구매·판매·최저가·베스트·추천 상품" 금지. "기준 충족", "이 조건으로 찾기"만.
- 가입 관련: "이메일로 저장" / "가입 없이 바로 시작해요" / "광고 메일은 보내지 않아요"만. "회원가입", "로그인하면 더", "지금 가입" 금지. 저장 링크는 항상 텍스트 링크, 버튼 아님(L8 안에서만 버튼).
- 섹션 제목 고정: "실제 이용 후기 — 이용이 확인된 분들만" / "WithSmall 소개 — 작은 친구의 첫 준비를 이렇게 도와요" . 소개 슬라이드 제목은 한 줄 주장형("'괜찮아요'가 아니라 28cm, 60×40cm로 말해요").

## 8. 플로우
**A 첫 방문(모바일)** `/` → 히어로 [동물 선택] → L1 골든햄스터 → 홈 개인화 → ② 칩 "! 쳇바퀴" → L4 → [규격 확인] L5 → 판정 → [이 조건으로 찾기].

## 9. 접근성·성능
레이어는 `role=dialog`, 포커스 트랩, ESC/뒤로가기 닫힘. 레일은 키보드 좌우·스크롤 스냅, 터치 타깃 44. 프리렌더 HTML에 레일 카드 본문 포함. LCP ≤ 2.5s(히어로 마스코트는 인라인 SVG).

## 9.1 이미지 원칙
- 실사 사진은 촬영본이 아니라 **무료 라이선스 이미지**(Wikimedia Commons CC0/CC BY, Unsplash·Pexels·Pixabay)만. CC BY-SA는 원본 그대로 쓰는 카드에만, 합성·히어로에는 쓰지 않음. 파일마다 출처·저작자·라이선스 기록, CC BY는 `/credits`에 자동 표기. 종·용품 기준에 어긋나는 사진(작은 쳇바퀴, 좁은 철망 케이지)은 쓰지 않는다. 장면 리스트·절차는 `이미지-소싱.md`. 실제 사육 환경(케이지 세팅, 쳇바퀴 설치, 치수 재기, 병원)을 우선, 동물 단독 '귀여운 컷'은 그룹 카드에만.
- 마스코트와 실사를 한 카드 안에 섞지 않는다.

## 10. 열린 질문
1. 데스크톱 L4/L7을 센터 모달로 할지 우측 드로어로 할지 — 첫 시안 후 결정(현재 드로어 480).
2. 홈 ②의 칩 레일에 REQUIRED만 보일지 권장까지 보일지(현재 REQUIRED + 미완료 우선).
3. 상품 ♥ 숫자 표시 임계치(현재 10).
4. 후기가 0개인 런칭 초기의 콜드스타트 홈은 4섹션 — 이때 ②를 대신할 것을 둘지(없음 유지 권장).
5. 이메일 저장 후 '내 친구' 여러 마리 지원 여부(현재 1마리, 동물 변경 시 덮어씀).
