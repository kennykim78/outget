## 0. 왜 다시 설계했나

v1.x는 기능적으로 맞았지만 **"준비해야 할 일의 목록"이 첫 화면**이라 관리자·CRM 도구처럼 보였다. 소비자 서비스의 리듬은 **발견 → 선택 → 도구**다(미리캔버스: 결과물이 가득한 첫 화면, 고르면 편집기가 열린다). v2.0의 원칙: **겉은 서비스, 속은 도구.** 홈은 카드와 레일로 발견하게 하고, 체크리스트·규격 확인·2질문은 레이어 안에서만 도구로 존재한다.

## 1. 디자인 원칙 (v2.0)

1. **한 화면 = 한 결정, 한 홈 = 하나의 다음 발견.** 홈은 "무엇을 해야 하지"만이 아니라 "다음에 무엇을 볼까"를 유도한다.
2. **동물을 고르는 순간 홈 전체가 개인화된다.** 동물 미선택 시 레일은 일반형("요즘 많이 찾는 준비"), 선택 시 "골든햄스터를 위한 준비"로 바뀐다. 이 전환이 "정적 정보 DB"와 "살아 있는 서비스"를 가른다.
3. **행동이 숫자보다 먼저.** "필수 2개 남았어요"가 진행률보다 먼저. 유지.
4. **근거는 항상 옆에.** 상품 카드에는 언제나 `○ 기준 충족`이 붙고, 판정에는 이유와 검수일이 붙는다. 신뢰 수치화 금지. 유지.
5. **안 사도 되는 것을 숨기지 않는다.** NOT_NOW는 체크리스트 레이어에서 항상 펼쳐 보이고(접힘·토글 없음), 선택 홈에도 「나중에 필요한 것」으로 보인다.
6. **시각 비중 고정: 캐릭터 > 구성안 > 용품 > 상품.** 상품 카드가 화면의 절반을 넘으면 쇼핑몰이 된다. 상품은 네 번째 레일이고 크기는 가장 작다.
7. **PC는 모바일의 확장이지 다른 제품이 아니다.** 상하 흐름 동일, 넓어지면 레일의 카드 수만 는다. 좌측 내비·고정 패널·2열 CRM 구조 없음.
8. **마스코트는 진입·개인화·빈 상태·완료에만.** 판정·규격·병원 상세·법적 안내에는 없음. 유지.
9. **의료 단정 금지, 흰 바탕 단일 테마.** 유지.
10. **콜드스타트는 '왜 WithSmall인가', 선택 홈은 '그래서 무엇을 준비할까'.** 미선택 홈은 히어로(큰 한 문장 + 선택 바) · 「처음 준비, 여기서 시작해요」 시작 카드 3 · 하단 CTA로 구성하고(후기·소개 슬라이드·기능 칩·시작 배너 마퀴 없음), 선택 홈은 컨텍스트 헤더 + 지금 필요한 것 · 나중에 필요한 것 · 처음 준비한다면 · 규격 확인 · 기준에 맞는 준비물 · 병원 · 저장 안내(§3.1). 스텝/특징 격자·카테고리 카드는 홈에 두지 않는다. 그룹 카드(소동물·앵무새 그룹 단위)는 두지 않고, 미선택 홈에는 노출 타입 카드(D4, 구현됨 — 홈 A ③)만 둘 수 있다.
11. **캐릭터는 대표 마스코트 하나, 나머지는 사진.** 마스코트는 진입·L1·빈 상태·완료에만(현재 구현의 홈 A 히어로·홈 B 컨텍스트 헤더에는 마스코트가 없다 — 시안 기준). 설명 블록·시작 카드·타입 카드·용품 카테고리의 사진 자리는 사진으로 채운다. **홈 사진은 생성 이미지를 임시로 쓴다(D14, 사용권 문제가 없는 생성분만, 실사진 확보 시 교체 — 교체 전 자리에는 「생성 이미지 · 임시」 표시).** 아이콘·이모지로 대신하지 않는다(구성안 글리프 🌿☁♻·상태 글리프 제외). 코드 반영 현황: 사진 슬롯(photos.json)은 전부 SLOT이라 현재 자리표시 — 생성 이미지 반영은 확인 필요.
12. **가입은 작고 자연스럽게 — '하다 보니 저장하고 싶어지는' 순서.** 이메일 링크 인증만, 저장 대상은 선택 동물·체크 상태·내 케이지뿐. 유도는 **2곳**: 선택 홈 저장 안내(텍스트 링크 「이메일로 저장하기」, 제목 「준비한 내용을 이어서 볼까요?」)와 L2 푸터("지금 준비 상태를 저장해 둘까요?"). 콜드스타트 홈·히어로·헤더에는 없음. 모달 강제·가입 게이트·기능 잠금 없음.

## 2. 정보구조

### 2.1 내비게이션 (상단 글로벌 헤더, 하단 탭바 없음)
```
≥768:  [WithSmall 로고]   준비물   크기 확인   병원   [친구 선택하기 | 동물 이름 칩]   (메뉴는 우측 정렬)
≤767:  [WithSmall 로고]                                                     [메뉴]
       [메뉴] 탭 → 헤더 아래 패널: 준비물 · 크기 확인 · 병원 · 칩
```
- 헤더 CTA 자리 = 선택 상태 칩(D1): 미선택이면 채운 버튼 「친구 선택하기」, 선택되면 동물 이름만 보이는 칩. 마스코트·▾ 없음. 탭하면 L1.
- 메뉴 3: 「준비물」(/supplies) · 「크기 확인」(동물이 있으면 그 동물의 규격 확인 대상, 없으면 L1을 거친 뒤 이동) · 「병원」(/vet).
- 모바일 하단 탭바 없음(D2). 메뉴 단추는 공개 내비게이션 패턴(aria-expanded·aria-controls, 열면 첫 링크로 포커스, Esc로 닫고 단추로 포커스 복귀, 헤더 밖으로 포커스가 나가면 닫힘, 포커스 트랩·스크림 없음). JS 준비 표식 전(번들 로드 실패·하이드레이션 전)에는 단추를 숨기고 메뉴 링크를 로고 옆 한 줄 가로 스크롤로 보인다(헤더 높이 불변). 토큰 `--ws-tabbar-h`는 정의만 남아 있고 미사용(탭바 없음).
- 소개·문의 페이지는 없다(D3, Phase 0 최소 범위). 푸터는 §2.4.
좌측 레일 없음. 칩이 "현재 컨텍스트"이며 어디서든 바꿀 수 있다.

```

 /supplies, /supplies/{item}   준비물(용품으로 찾기) — 카테고리 그리드 → 동물 선택 → 용품 레이어
 /vet, /vet/{region}       병원 — ≥1024 목록|지도 나란히, ≤1023 목록·지도 탭 전환, 전문 도구 톤
 404 · PLANNED · 오프라인

레이어 (부모 페이지는 유지되고 URL만 history state로 확장: `/hamster/golden` → `/hamster/golden/supplies/wheel`, 뒤로가기 = `/hamster/golden`. 딥링크 시 "부모 페이지 + 레이어 열림"으로 렌더. 모바일 바텀시트 / PC 센터 모달 — 모든 레이어 동일, 드로어 없음)
 L1 동물 선택      소동물|앵무새 → 세부 타입 → "잘 모르겠어요"(별칭)
 L2 체크리스트     필수/권장/선택/NOT_NOW, 상태 엔진, [내 상황 다시 설정]
 L3 2질문          처음/이미 · 가진 것 (L2 첫 진입 시 L2 안에서 스텝으로)
 L4 용품 상세      왜/조건/주의/피할 것/대안 · 내 케이지 호환 · 하단 [규격 확인][이 조건으로 찾기]   URL /{group}/{type}/supplies/{item}

 L6 내 케이지      타입·치수 (L5·L2에서 스텝으로)
```

### 2.4 푸터 (D3 최소 범위)
로고 · 한 줄 소개(「작은 친구와 함께하는 첫 준비」) · 링크 「개인정보 처리방침」·「사진 출처」(/credits — 이미지 사용권 공개) · 「의료 판단을 대신하지 않아요」 · © WithSmall. 소개·문의 링크는 없다. 제휴 링크가 보이는 화면(L4·L7·`/supplies/{item}/{type}`, 몰 상품 레일이 있는 선택 홈)에서는 © 바로 위에 제휴 고지 한 문장이 더 붙는다(아래 「제휴 하단 고지」).

## 3. 홈 (`/`, `/{group}/{type}`)

### 3.1 두 개의 홈 (고정)
**A. 동물 미선택(콜드스타트)** — 구현 현황: 아래 ①②③④ 모두 구현됨(③ = 286 U3c~U3e)
```
① 히어로        큰 한 문장 「작은 친구와의 시작, 꼭 필요한 것부터」 + 부제 「준비물부터 크기까지, 함께 골라요.」 + 선택 바 1(입력이 아니라 /pick 링크, 하이드레이션 후 L1). 저장된 동물이 있으면 「이어서: {동물}」 링크(자동 이동 없음). 기능 칩 없음
② 시작 카드      「처음 준비, 여기서 시작해요」 3카드: 꼭 필요한 것 먼저(체크리스트) · 크기 확인(L5) · 구성안(/setup). PC 3열 / ≤767 가로 레일. 동물이 없으면 L1을 거쳐 그 카드의 대상으로 이동, 있으면 바로 이동. 노출 타입 0이면 섹션 없음, 대상 없는 카드는 빠진다
③ 설명 섹션(구현됨, `Explain.tsx`)   순서: 「지금 필요 없는 것도 알려 드려요」(필요해요 / 지금은 필요 없어요 2열 — 시드 레코드만) → 「숫자로 알려 드려요」(대표 타입의 최소 규격 큰 숫자 — 시드·엔진 값만) → 「함께 살 집을 살펴봐요」(노출 타입 카드: ACTIVE만, PLANNED 제외, 카드 → 타입 홈, D4) → 「진료하는 병원만 보여 드려요」(진료 동물별 집계만 — 병원 이름·지도 그림 미노출). 데이터가 없는 부분은 숨기고 노출 타입이 0이면 섹션 전체가 없다. 서버 프리렌더 `misc.ts homeExplain`과 같은 마크업
④ 하단 CTA      「어떤 친구와 함께하나요?」 + 「친구 선택하기」(문장 좌·버튼 우, ≤767 세로). 저장 유도 없음
```

## 4. 레이어 명세

**L1 동물 선택** — 그룹 2(사진 카드 2패널, 선택 후 주 버튼 「{그룹} 친구 고르기」로 타입 단계 교체 — 구현 현황, 확인 필요) → 타입 카드(ACTIVE/PLANNED) → "잘 모르겠어요" 텍스트 입력·별칭 후보(종 확정 안 함). 선택 즉시 닫히고 홈이 개인화됨(`species_selected`).
**L2 체크리스트** — 머리 「꼭 필요한 것 먼저」 + 「{동물}의 첫 준비예요」 + 「꼭 필요한 것 N개 남았어요」(현재 구현), 그룹 행(필수 · 「있으면 좋아요」(권장·선택, 펼친 섹션 유지 — D8; 현재 코드 그룹 라벨은 「권장」·「선택」, 문구 반영 확인 필요) · 「지금은 필요 없어요」 — 모두 항상 펼침, 접힘·토글 없음). 상태 엔진 ✓ 준비완료 · ! 먼저 준비 · △ 확인 필요(§5.1), 「나중에」는 단어만. 보유 라벨, NOT_NOW 이유 · 행 이유 한 줄 = 호환 이유(△) > NOT_NOW 이유 > whyShort > why 첫 문장, [내 상황 다시 설정](L3 스텝). 행 탭 = L4로 교체(뒤로가기 시 L2 복귀). 첫 진입엔 L3가 먼저 스텝으로 뜬다(건너뛰기 가능).
**L4 용품 상세** — 본문 순서 「규격 → 검수 → 상인 링크」(구현 `SupplyLayer.tsx`, R4 시안 l4_supply): (제휴 링크가 그려지면 고지 B) → 「동물 · 용품」 눈썹 → 메타 행 → 사진 자리 → 왜 → 조건(최소·권장) → 주의 → 피할 것 → 대안 → 내 케이지 호환 서브카드 → [준비했어요] 버튼 → 「이 항목에 맞는 준비물」 상품 카드(있을 때, 앞 3) → 몰 상품 블록 「몰 검색 결과」(피드를 켠 빌드에서만 — 행마다 가격·확인일·「제휴 링크」·「쿠팡에서 보기」, 블록 안 제휴 고지) → 「검수 내용」 섹션(마지막 검수 · 출처 · 👍 ⚠) → 「이 조건으로 찾기」 검색 블록(상인 링크). 푸터 [규격 확인](채움)·[이 조건으로 찾기](아웃라인 — 검색 블록으로 이동).
**L5 규격 확인** — specSchema 폼, 내 케이지(L6 스텝), **2단 판정**(제품 규격 / 내 환경 호환; 판정 글리프·단어는 §5.1), 대안, [이 조건으로 찾기] 검색 블록(검색어·복사·쿠팡/네이버 버튼). 검색 블록은 판정 결과와 함께 처음부터 펼쳐 둔다 — 펼침 버튼·접기·더보기 없음(제휴 여부와 무관). 제휴 링크가 있으면 고지 A(상인 버튼 바로 위)·B(레이어 본문 첫 요소)(PRD US-012).
**L5 후기 「크기 확인에 도움 된 점」(구현됨 D6-B — `SpecReview.tsx`, R5 안 B)** — 결과 설명 다음·기존 버튼 앞에 승인 원문 1건(카드 없이 선 1개 + 텍스트). 노출 조건: APPROVED ∧ verifiedUsage이고 현재 결과의 동물·용품 맥락과 연결된 것만. 현재 화면에 맞는 후기가 0건이면 제목·선·여백까지 렌더링하지 않는다(「후기가 없어요」·작성 유도 없음). 별점·인기 지표로 고르지 않고, AI·운영자가 문장을 쓰거나 고치지 않는다. 후기는 판정을 바꾸지 않으며 「같은 규격으로 준비한 분」 표현은 규격 일치가 확인될 때만 쓴다. 구현: 같은 문서의 승인 후기 중 이 동물 ∧ `linkedAction=SPEC_CHECK`의 첫 1건(원문 그대로, 「{동물} · {상황}」 한 줄), 0건이면 null, 예시 문구는 화면에 없다. 현재 연결은 동물·`linkedAction`뿐이라 용품 단위 연결·발췌 정책은 확인 필요.
**L8 이메일 저장** — 제목 "이메일로 저장해 둘까요?", 설명 "선택한 동물과 준비 상태만 저장해요. 비밀번호 없이 메일의 링크로 확인해요.", 이메일 입력 1개, 저장 대상 요약 한 줄(동물 칩 · 필수 N개 남음 · 내 케이지), 입력 라벨 「이메일」·자리 표시 `name@example.com`, 채운 버튼 하나 [저장 링크 받기](구현 `SaveLayer.tsx`·`copy.ts save.*`, 이전 「인증 메일 보내기」), [나중에 할게요] 아웃라인, "광고 메일은 보내지 않아요". 링크 만료 화면의 재전송 버튼 문구는 현 코드 그대로 「인증 메일 다시 보내기」(보냄 화면은 「다시 보내기」). 링크 클릭 시 로컬 상태를 서버로 병합(로컬 우선). 로그인 상태 표시는 헤더 동물 칩 안 이름 바로 뒤 6px 점 하나(`SaveDot`).
**제휴 하단 고지(F, 구현됨 R4-3)** — 제휴 링크가 보이는 화면(L4·L7·`/supplies/{item}/{type}`, 몰 상품 레일이 있는 선택 홈)에만 페이지 하단, 푸터 © 바로 위에 쿠팡 파트너스 고지 원문 한 문장(접힘 없음, `note-f`). 제휴 링크가 없으면 그리지 않는다. 그릴 상인 링크가 0이면 비활성 상인 버튼 「상인 링크 준비 중」. L5는 레이어 안 고지 A·B만(푸터 고지 없음). 운영자 확인 상품 단위 제휴·가격·판매처는 여전히 없다(몰 상품 피드는 §5).

**L4·L7 셸** — 드로어 없이 다른 레이어와 같은 모달 720(≥1024)/600(768~1023)/바텀시트(≤767). 모달은 제목행 + ✕ + 구분선 고정, 본문은 최대 높이 안에서 스크롤, 하단 주 버튼 고정 슬롯. **L7 상품 상세** — 본문 순서 「규격 → 검수 → 상인 링크」(구현 `ProductLayer.tsx`): (고지 B) → 「동물 · 용품」 눈썹 → 이미지(운영자 확보분, 없으면 대체 타일 「이미지 준비 중」) → ○ 기준 충족 + ♥ → 규격 한 줄 → 마지막 검수 → **WithSmall 추천 이유(자동 조립: 규격 충족 · 프로필 일치 · 호환)** → 용품 기준 링크 → [이 조건으로 찾기](검색 딥링크) 검색 블록을 본문에 처음부터 펼쳐 둔다 — 펼침 버튼·접기·더보기 없음(제휴 여부와 무관). 꼬리 버튼을 두면 검색 블록으로 이동(스크롤·포커스)만 한다(L4와 같음). 제휴 링크가 있으면 고지 A·B(PRD US-012). 운영자 확인 상품 단위 가격·판매처·제휴 없음(Phase 1, 몰 상품 피드는 L7을 열지 않는다). "구매" 단어 없음.

## 5. 상품 표면 규칙 (Phase 0 = 발견, 판매 아님)
- 카드: 이미지(1:1, 상품이 화면의 주인공이 되지 않도록 카드 폭 ≤ 200), 상품명 1줄, 규격 한 줄(`30cm · 무소음`), `○ 기준 충족` 배지(항상), ♥(반응 수는 임계치 이상일 때만 숫자 표시, 미만은 아이콘만).
- 레일 제목은 "기준에 맞는 준비물"(검수 기준) — "많이 선택한 준비물"(♥ 기준)은 데이터가 쌓인 뒤 별도 레일로, 절대 같은 레일에 섞지 않음. 노출 순서 규격→검수→선호 고정.
- 이미지 출처: 운영자가 사용권을 확인한 이미지(직접 촬영·판매자 허가·제휴 API 제공분)만. 외부 페이지 자동 수집 금지. 이미지 없는 상품은 카드에 용품 아이콘 타일로 대체.
- 상품 카드에 캐릭터·가격·"최저가"·"베스트" 없음.
- 몰 상품 피드(11/23 합의안·보안 375 S2, 피드를 켠 빌드에서만 — 기본 꺼짐)는 위 운영자 확인 카드와 섞지 않는다. 홈은 별도 레일 「몰에 올라온 상품」(「표기 규격 통과」 카드만), L4는 상품 카드 뒤 블록. 가격·확인일(확인 72시간 안에서만)과 몰 버튼 「쿠팡에서 보기」가 있고 `○ 기준 충족`·♥ 는 없다. 홈 레일 머리에는 제휴 고지 1회(가격을 보일 때는 「몰 가격은 확인한 날 기준이에요. 몰에서 달라질 수 있어요.」도).

### 5.1 판정 글리프 (R4-1 구현 · 단일 소스 `GLYPH`)
글리프 + 색 + 단어를 항상 함께(색만으로 말하지 않는다).
| 구분 | 글리프 | 단어 | 쓰는 곳 |
|---|---|---|---|

## 9. 접근성·성능
레이어는 `role=dialog`, 포커스 트랩, ESC/뒤로가기 닫힘. 모바일 메뉴는 모달이 아니라 공개 내비게이션(포커스 트랩 없음, Esc 닫힘·단추로 포커스 복귀). 레일은 키보드 좌우·스크롤 스냅, 터치 타깃 44. 프리렌더 HTML에 레일 카드 본문 포함. LCP ≤ 2.5s(히어로 마스코트는 인라인 SVG).

## 9.1 이미지 원칙
- **홈 사진(D14, Kenny 2026-11-14)**: 생성 이미지를 임시로 쓴다 — 사용권 문제가 없는 생성분만, 화면에 임시 표시, 실사진(아래 무료 라이선스·촬영본) 확보 시 교체. 코드 반영 전까지 자리표시(PhotoTile)이며, 생성분의 `imageLicense`/`source` 기록 방식은 확인 필요(불변식 1).
- 실사 사진은 촬영본이 아니라 **무료 라이선스 이미지**(Wikimedia Commons CC0/CC BY, Unsplash·Pexels·Pixabay)만. CC BY-SA는 원본 그대로 쓰는 카드에만, 합성·히어로에는 쓰지 않음. 파일마다 출처·저작자·라이선스 기록, CC BY는 `/credits`에 자동 표기. 종·용품 기준에 어긋나는 사진(작은 쳇바퀴, 좁은 철망 케이지)은 쓰지 않는다. 장면 리스트·절차는 `이미지-소싱.md`. 실제 사육 환경(케이지 세팅, 쳇바퀴 설치, 치수 재기, 병원)을 우선, 동물 단독 '귀여운 컷'은 그룹 카드에만.
- 마스코트와 실사를 한 카드 안에 섞지 않는다.
