# WithSmall — Claude Code 다중 에이전트 킥오프

Cowork(기획·디자인)에서 Claude Code(구현)로 넘기는 인수인계 문서. 코드 복구(§7.4)부터는 Claude Code에서 `withsmall-build` 오케스트레이터가 일괄 진행한다.

## 1. 구조 (누가 무엇을, 어떤 모델로)

```
Kenny ──(결정 6종만)──▶ 오케스트레이터 (메인 스레드, opus, skill: withsmall-build)
                              │  판단 · 계획 승인 · 디스패치 · 게이트 · decisions.md
        ┌─────────────┬───────┼──────────┬──────────────┬───────────────┐
   architect      design-liaison   backend-engineer  frontend-engineer   small-dev
    (opus)           (opus)            (opus)            (opus)          (sonnet)
   계획·영향       DS/캔버스→스펙,      스키마·시드·엔진·   홈·레일·레이어·    ≤2파일 명세형
                   화면 검수(10항목)     API·프리렌더        병원·반응형        카피·토큰·테스트
        └─────────────┴───────┬──────────┴──────────────┴───────────────┘
                        qa-verifier (opus) — 모든 단계 뒤 적대적 검증 + 불변식 스캔
                        security-auditor (opus) — 스키마·시드·노출·외부·이미지·메일 변경 시
                        content-curator (sonnet) — 시드 검증·린트 (사실 창작 금지)
                        refactorer (sonnet) — 동작 불변 정리
   도구 스킬: knockedu-qa · run · test · screens(390/1280) · contract · impact
```

**모델 등급 원칙:** 판단·설계·게이트·큰 구현 = opus. 명세가 완전하고 ≤2파일이며 결정이 없는 일 = sonnet. 애매하면 opus. 각 `Agent` 호출에 `model`을 명시한다(에이전트 파일 frontmatter에도 고정).

**Kenny가 결정하는 6가지(그 외는 오케스트레이터가 결정하고 `_workspace/decisions.md`에 기록):**
1. 불변식·동결 범위 변경(§9 백로그, 새 동물, 가격·제휴·계정 확장)
2. 돈·계정·키·외부 서비스 가입(지도 키, 제휴 API, 메일 발송)
3. 홈 섹션 구조·레이어 세트(L1~L8)·디자인 토큰 색/타입 변경
4. 시드의 사육·먹이·규격 **사실**(에이전트는 플래그만)
5. 파괴적 git·프로덕션 배포·콘텐츠 공개
6. 같은 단계 검증 2회 실패

## 2. 사전 준비 (한 번, 터미널에서)

Cowork는 `.claude/`에 직접 쓸 수 없어 하네스 설정이 `harness-config/`에 들어 있다. 설치 스크립트가 `.claude/agents`·`.claude/skills`를 덮어쓰고 `settings.json`에 `model: opus`를 병합한다.

```powershell
cd C:\kenny_work\260607_outget
node scripts/install-harness.mjs
claude
```

세션 안에서 `/agents`에 architect·backend-engineer·frontend-engineer·design-liaison·qa-verifier·security-auditor·small-dev·content-curator·refactorer 9개, `/skills`에 `withsmall-build`가 보이면 준비 끝(안 보이면 `claude` 재시작). 키는 아직 넣지 않는다 — 지도 키·메일 발송은 R5에서 오케스트레이터가 Kenny 결정 항목으로 올린다.

## 3. 첫 프롬프트 (그대로 붙여 넣기)

```
withsmall-build 스킬로 진행한다. Outget → WithSmall 피벗의 코드 복구를 R0부터 시작해라.

권위 문서: docs/WithSmall-제품기획-v0.2.md(v0.2.3, 특히 §5 스키마·§7.4 복구 순서), docs/planning-artifacts/PRD.md(v1.3), UX-기획.md(v2.3.1), 디자인-브리프.md, docs/design/, 골든햄스터-콘텐츠-시드-v1.0.md + seed-draft/.

이번 세션 목표: R0(보존 브랜치) → R1(Outget 모듈 제거 + WithSmall 스키마 적용 + typecheck 통과) → R2(시드 로더·seed:validate·엔진 3함수 + 테스트)까지. 각 라운드 끝에 knockedu-qa 게이트와 decisions.md 요약을 보고하고 다음 라운드로 넘어가라.

결정 권한 매트릭스를 지켜라: 6가지 외에는 묻지 말고 결정·기록·진행. 모든 Agent 호출에 model을 명시(architect/backend/frontend/design-liaison/qa/security = opus, small-dev/content-curator/refactorer = sonnet). 빌드·테스트 증거 없이 done 보고 금지.
```

이후 세션: `withsmall-build로 R3(프리렌더·컴플라이언스 스캔 교체)부터 이어서.` / `R4 클라이언트 골격 — design-liaison 스펙 먼저.` / `R5 레이어·병원·이메일 저장.` / `R6 골든햄스터 완주 테스트와 게이트.`
