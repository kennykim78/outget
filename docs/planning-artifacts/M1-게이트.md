## ① 외부 P2P 안전결제 — 제공사 서면(메일) 확답  🔴 외부

**왜 게이트인가:** 불변식 ②(자금 미보유)를 지키려면 *플랫폼이 자금을 보유·정산하지 않고* 개인↔개인 거래를 외부 안전결제로 연결해야 한다. 그런데 일부 안전결제/페이링크 약관은 **구매대행(용역성)·C2C**를 금지한다. 약관 위반 시 서비스가 막히므로 **개발 착수 전 서면 확답** 필수. 확답 전까지 결제 어댑터는 '안내 모드'(직접거래 + 가이드)로만 가동(이미 그렇게 설계됨).

**후보 제공사(확인 대상):** NHN KCP 페이링크 · 토스페이먼츠(안전결제/링크) · 네이버페이 안전거래 · 카카오페이/당근페이류 안전결제.

**확답받을 핵심 질문 3가지:**
1. 당사는 **결제에 관여하지 않는 정보·매칭 플랫폼**이다. 이용자(개인 구매자·개인/전문 대행자)가 **개인 간 "구매대행/심부름" 명목** 거래에서 귀사의 페이링크/안전결제를 **채팅으로 공유해 사용**해도 약관상 문제가 없는가?
2. 자금이 **당사(플랫폼) 명의 계좌·PG 가맹점을 일절 경유하지 않고** 구매자→(귀사 에스크로)→대행자로 직행하는 **비수탁 구조**가 귀사 상품으로 가능한가?
3. 구매대행/C2C/용역 거래에 대한 **금지·제한 조항**이 있는가? 있다면 허용 범위·조건은?

**메일 초안(국문):**
```
제목: [제휴문의] 개인 간 구매대행 거래의 안전결제(페이링크) 이용 가능 여부 확인

안녕하세요. 지도 기반 아울렛 구매대행 매칭 서비스 'Outget(아웃겟)'을 준비 중인 [이름/사업자]입니다.

당사는 구매자와 현장 구매대행자를 '정보·매칭'으로 연결하는 플랫폼으로,
결제에 직접 관여하지 않으며 자금을 보유·정산하지 않습니다.
이용자 간 안전한 거래를 위해 귀사의 안전결제(페이링크)를 안내하려 하며,
약관 적합성을 사전에 확인하고자 합니다.

1) 개인 구매자와 개인/전문 대행자가 '구매대행/심부름' 명목의 개인 간 거래에서
   귀사 페이링크를 채팅으로 공유·사용하는 것이 약관상 허용되는지요?
2) 결제대금이 당사(플랫폼) 계좌·가맹점을 경유하지 않고
   구매자 → 귀사 에스크로 → 대행자 로 직행하는 비수탁 구조가 가능한지요?
3) 구매대행/C2C/용역 거래에 대한 금지·제한 조항이 있는지, 있다면 허용 조건은?

가능하시면 서면(메일) 회신 부탁드립니다. 감사합니다.
```
**산출 기준(게이트 해제):** 위 1~3에 대해 **허용**한다는 서면 회신 1곳 이상 확보 → 그 제공사로 결제 어댑터 구현(Epic 5).

## ② 법률 자문 — 질의서  🔴 외부(변호사)

불변식이 "리스크 분석" 위에 서 있으므로, 베타 전 변호사 검토로 전제를 확정한다.

**질의 항목:**
1. **통신판매중개자 지위·책임** — 정보·매칭 전용(당근형) 모델에서 전상법 §20(고지)·§20-2(연대책임) 의무 범위. "직접거래 미추적"이 분쟁처리 협조의무와 충돌하는가? 유지해야 할 최소 의무(고지·신원정보 제공·분쟁 채널)의 구체 수준.
2. **개인 대행자 사업자등록 임계** — 반복·영리 구매대행이 통신판매업 신고/사업자등록 의무가 되는 기준(횟수·금액). 플랫폼의 의뢰자 정보 제공 의무 범위. 개인/전문 구분·고지로 충분한가.
3. **UGC 책임 경계** — 할인소식(미검증·`기준가 미확인` 라벨)의 표시광고법 책임, 사용자 불펌 사진의 저작권 책임, notice-and-takedown(즉시 블라인드+이의)으로 OSP 면책 성립 요건.
4. **공동대행 세무** — 대행자 다건 구매가 사입(도소매)으로 간주되는 기준, 경고·결제후구매 안내로 플랫폼 방어 충분한가.
5. **외부 안전결제 안내** — 플랫폼이 결제에 관여하지 않고 링크를 "안내"만 할 때(검증·보증 안 함) 자금세탁방지·전자금융 규제 적용 여부.

**산출 기준:** 위 5개에 대한 의견서 → 불변식·고지 카피·등록 플로우 확정 후 Epic 3/5/6 구현.

## ③ 데이터 저장소 확정  🟡 내부 (권고: PostgreSQL)

- **권고: PostgreSQL + Prisma(ORM).** 매칭·거래·신고의 관계/상태머신에 적합, 관리형(RDS/Supabase/Neon) 흔함. 현재 server는 인메모리 stub + `Repository` 포트라 **교체 비용 낮음**(Epic 3+ 영속화 시 어댑터만 구현).
- 대안: SQLite(개발/소규모) → 추후 PG 이전. 결정 시 `architecture.md §2` 갱신 + ORM 배선.
- **결정 필요:** PG 채택 확정 여부 + 관리형 제공자.

## ④ 호스팅/배포 타깃  🟡 내부 (권고)

- 클라(PWA): 정적 호스팅 — Vercel / Cloudflare Pages / Netlify.
- 서버(Express): 컨테이너 — Fly.io / Render / Railway.
- DB: 관리형 PostgreSQL.
- **결정 필요:** 각 타깃 1개씩 선정 → CI 배포 스텝 추가.

## ⑤ 앵커 지역  🟡 내부 (권고: 여주)

- **권고: 여주 프리미엄아울렛** — 국내 최대급, 브랜드 다양성·할인 콘텐츠 풍부 → 추정/제보 시드 만들기 유리(PRD 가설). 김포는 수도권 서부 접근성↑로 2차 후보.
- 아키텍처 비종속 — `useDefaultRegion`의 동 중심 좌표 상수만 수정하면 됨.
- **결정 필요:** 1차 앵커 확정.
