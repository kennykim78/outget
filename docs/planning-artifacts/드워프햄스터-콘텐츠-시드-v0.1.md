# 드워프햄스터 콘텐츠 시드 — 검수 입력 양식 v0.1

> 이 문서는 **빈 양식**이다. 사실(수치·사육·먹이·법·규격)은 한 글자도 미리 채워져 있지 않다. 사실 칸은 검수자만 채운다.
> 미리 채워진 것은 Kenny가 정한 데이터 입력 값(학명·id·대표 종·프로필 id)뿐이다.
> 사양 근거: `_workspace/58a_curator_dwarf_form_spec.md`, 구성: `_workspace/58_architect_r7_dwarf_plan.md`, 결정: `_workspace/55_curator_dwarf_seed_plan.md` §3-1 + decisions.md 2026-10-15.

---

## 0. 머리말

### 0-1. 목적
드워프햄스터(정글리안·캠벨)의 시드(Taxon 2·CareProfile 1·SupplyRequirement 14·CompatibilityRule 판단·SetupBundle 3·AnimalType 연결)에 들어갈 사실을 검수자가 직접 적어 넣는 입력 양식이다. 이 양식이 서명되기 전에는 시드 파일에 사실 행을 넣지 않는다.

### 0-2. 원칙
1. 사실은 검수자만 적는다. AI·운영자는 옮겨 적기만 한다.
2. `AI_DRAFT`는 어떤 경우에도 `VERIFIED`가 될 수 없다.
3. 골든햄스터 값을 복사하지 않는다. 같아 보여도 이 양식에서 새로 확인해 적는다.
4. 출처는 실제로 열어 본 것만 적는다. 지어내지 않는다. 출처가 없으면 그 칸은 공란이고, 그 행은 `VERIFIED`가 될 수 없다.
5. 비울 칸은 **공란**으로 둔다. `[검수 필요]` 같은 표시 문자열을 시드로 옮기면 린트 L04 오류가 난다. 시드에서는 `null`로 옮긴다.
6. 판단이 안 서는 칸은 비워 두고 아래 '메모'에 이유를 적는다.

### 0-3. contentKind별 VERIFIED 최소 등급·출처 수

| contentKind | 해당 | 최소 reviewerType | 출처 수 | 비고 |
|---|---|---|---|---|
| SPEC | 규격 (용품 규칙, 호환 규칙) | EXPERIENCED_KEEPER 이상 | 1 이상 | |
| CARE | 사육 (프로필, 번들, 사육 요구사항) | EXPERIENCED_KEEPER 이상 | 1 이상 (2 권장) | |
| FOOD | 먹이 | VET_PUBLISHED_SOURCE 이상 | 서로 다른 도메인 2 이상 | 아래 국내 수의 체크 |
| HEALTH | 건강 | VET_PUBLISHED_SOURCE 이상 | 서로 다른 도메인 2 이상 | 아래 국내 수의 체크 |
| LEGAL | 법 (Taxon 전용) | OFFICIAL_SOURCE 정확히 | 1 이상 | 동물단체 페이지는 부적합, 법령 원문만 |

reviewerType 등급 순서: AI_DRAFT < OPERATOR < EXPERIENCED_KEEPER < VET_PUBLISHED_SOURCE < OFFICIAL_SOURCE < VET.
VERIFIED 행은 verifiedBy(핸들)와 verifiedAt(YYYY-MM-DD, 미래 날짜 불가)이 필수. 검수일이 오래되면 노출에서 제외된다(경고 W-STALE).
VERIFIED 요구사항이 가리키는 SupplyItem·CareProfile도 VERIFIED여야 한다.

### 0-4. FOOD·HEALTH 국내 수의 출처 확인 (검증기 밖, 사람이 확인)
FOOD 또는 HEALTH 행을 VERIFIED로 올리려면 아래를 모두 체크한다.

- □ 서로 다른 도메인 출처가 2건 이상이다.
- □ 그중 국내 수의 관련 출처가 1건 이상이다.
- □ 출처 본문에서 해당 문장의 근거를 직접 확인했다.

확인자: ______________  확인일: ____-__-__

### 0-5. 문장 린트 요약 (문장 칸을 적을 때)
- 금지어 목록(`banned-words.json`)에 있는 말을 쓰지 않는다. 정확히 일치하면 오류, 어간이 비슷하면 경고다. 목록은 프로젝트 CLAUDE.md 불변식 5에 있다.
- why는 2문장 이하, caution은 1문장.
- 숫자에는 반드시 단위를 붙인다(숫자만 단독으로 쓰지 않는다). 범위는 한 묶음으로 쓴다.
- 자리표시 문자열(빈 문자열·대시·TODO·TBD·N/A·대괄호 표시)을 시드에 쓰지 않는다. 비울 칸은 `null`.
- 의료 판단 금지: '병원에 문의할 상황'까지만 쓴다.
- 검색어(searchKeyword)를 직접 쓸 때는 `{animal}`을 포함한다.

## 4. SupplyRequirement × 14

공통 안내:
- 행 = `cp-hamster-dwarf` × 용품. id 규칙은 `req-dwarf-{용품id}` (이관 시 오케스트레이터가 부여).
- 용품 specSchema는 기존 SupplyItem 것을 그대로 쓴다. 없는 key·없는 선택지가 필요하면 각 블록 끝의 'specSchema 필드 추가 요청' 칸에 적는다(SupplyItem 변경이므로 architect·Kenny 결정 대상, 골든 평가에 영향).
- priority 선택지: REQUIRED / RECOMMENDED / OPTIONAL / NOT_NOW. orderHint 선택지: BEFORE_ARRIVAL / FIRST_WEEK / AFTER_ADAPTATION / AS_NEEDED.
- NOT_NOW일 때만 notNowReason을 적는다(아니면 공란).
- REQUIRED·RECOMMENDED는 searchKeyword를 비우지 않는다. 기본 규칙으로 충분하면 '기본 사용'에 체크, 직접 쓰면 `{animal}` 포함.
- 규칙 표의 op 허용값: number는 gte·lte·eq·in·not_in, boolean은 eq만, enum은 eq·in·not_in(선택지 안 값만). 규칙끼리는 AND. 규칙마다 reason 필수(산문).
- when(조건부 규칙)이 필요하면 reason 칸에 '조건: key op value' 형식으로 적는다.
- 아래 각 블록의 '입력 허용 범위(기준값 아님)'는 입력 가능한 숫자의 한계일 뿐 사육 기준이 아니다.
